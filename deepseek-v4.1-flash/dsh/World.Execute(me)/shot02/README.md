# world.execute(me); — 程序生成同人 MV

Mili《world.execute(me);》的同人 MV。**画面 100% 由代码生成**：一个在浏览器里跑的
WebGL2 程序，每一帧都是时间 `t` 的纯函数，逐帧计算并由 WebCodecs 编码成
1920×1080 @ 60fps 的视频成品。

> 原曲：Mili – world.execute(me);（专辑 *Miracle Milk*, 2016）
> 本作是非商业同人作品，音频版权归 Mili 所有。

## 一、先听懂这首歌

**事实**：Mili，2016 年 6 月 12 日官方投稿，收录于 2016 年 10 月 12 日专辑《Miracle Milk》
（SIHT-1004，第 11 首）。词：Cassie Wei（momocashew，大学读的是软件工程）；曲：Mili /
Yamato Kasai。标题末尾的分号是作品的一部分 —— 它是一行 Java 方法调用。

**立意**：`world.execute(me);` 是在对象 `world` 上调用 `execute()`，把自己当参数传进去。
`execute` 同时是「运行一个程序」和「处死一个人」。整首歌就活在这个双关里：**「世界，运行我」
和「世界，杀了我」是同一句话。**

**叙事**：第一人称的「我」是程序 / 模拟体，对「你」（使用者、创造者、这个世界的上帝）独白。
「你」全程没有回答。开头的上电流程写得像求爱，第一段是数学式的自我奉献（我是点，就把维度给你；
我是圆，就把周长给你；我是正弦，就把切线给你坐；我趋向无穷，你就是我的极限），第二段忽然变成
茄子、番茄、猫这些可以吃、可以摸的东西——像是程序在学着当人。副歌是誓言，也是笼子：
「我们可以给你这一切，我会运行那次执行」——自我处决既是爱的信物，也是被判的刑。
第二段副歌转冷：「如果你走了」，五次堆叠，落到「隔离」。桥段是审判：程序用它自己创造者的
技术语言指控创造者「你写了非法的参数」。执行段是十二次 EXECUTION 的念诵，接着一至六用六种
语言数出来，再一句 EXECUTION。尾声最轻最狠：我学过怎么好好爱人、我懂爱的代数表达式、
**你是自由的，我被困住**——困在爱里。最后一次执行，乐器把它带走。

**音乐结构（实测）**：4/4，**130.00 BPM**，第一个强拍落在 **0.217 s**；这首歌是模块化的，
由 **14 个 8 小节块**拼成，每块 **14.769 s**。同一段器乐 riff 在 0:15 / 2:13 / 3:11 出现三次。
换句话说，**这首歌本身就是一个循环**——这一点直接决定了 MV 的骨架（见下）。

这些数字不是猜的：`_dev/bake-audio.mjs` 把音轨切成每视频帧（60 Hz）一条的特征曲线；
`_dev/grid.mjs` 用梳状滤波在整首歌上搜索速度与相位，得到 130.00 BPM / phase 0.217 s；
再拿它对齐 `_dev/ssm.mjs` 画出的自相似矩阵与 420 个实测瞬态，误差在 0.05 s 以内。

## 二、视觉概念：一张无限大的坐标纸，和一个把自己画出来的程序

> **The Limit** —— 一张无限延伸的坐标纸悬在虚空里，一个程序在上面一遍遍试着把自己画成
> 某种东西；每一次都差一点，因为它的形状取决于「你」在不在。

* **世界**：一张无限坐标纸，浅青色的网格在雾里退向地平线，天上有缓慢移动的星和一个很淡的
  月亮。没有贴图、没有模型，全部由片元着色器算出来。它在不同段落里变成电路板、法庭、
  被撕开的纸、反面印刷的相纸。
* **主角**：一团**半调（halftone）图形**。它不是机器人也不是女孩——它是同一条 SDF 轮廓在
  不同小节里换身体：点 → 圆 → 正弦 → 无穷 → 人 → 茄子 → 番茄 → 猫 → 机器 → 分身 → 点。
  每个身体外部都有一圈柔和的暗晕，让细线在这种网格背景上读得出来。
* **视觉副歌**：三个器乐 riff 段（0:15 / 2:13 / 3:11）用**完全同一个镜头**——低空掠过坐标纸。
  第一次是正片，第二次是**负片**（墨印在纸上的反相），第三次程序已经不在了，只剩一个光标。
* **地板上的代码**：一首歌的「歌词」被写在坐标纸的地板上，镜头贴着它飞过去，
  在透视里向远处滚动。观众是从代码上面飞过去的。
* **文字**：屏幕上出现的每一句都是我**自己写的**，用这首歌自己的语法（if / then）说话，
  不是歌词转录。它是程序的心声，不是字幕。
* **没有一帧是随机的**：所有「随机」都是 `hash(i)`、`hash12(p)`；没有 `Math.random()`，
  没有上一帧的累积缓冲，没有读挂钟时间。

## 四、渲染管线

```
                    ┌──────────────── 每一帧（纯函数）────────────────┐
 t = frame / 60  →  │ world 片元着色器：坐标纸 / 电路 / 裂缝 / 雾 / 月 │
                    │        ↓ RGBA16F FBO                            │
                    │ 实例化精灵（≤40000）：环、辐条、尘埃、栏杆、分身 │
                    │        ↓                                        │
                    │ 3D 文字：写在地板上的代码，透视滚动              │
                    │        ↓                                        │
                    │ 主角：半调 SDF 形变（12 种身体 + 拓扑等高线）    │
                    │        ↓                                        │
                    │ 屏幕文字（字形图集，一次 Canvas2D 烘焙）         │
                    └────────────────────────────────────────────────┘
                                     ↓
                    三级高斯泛光（阈值 1.0，只让 HDR 部分发光）
                                     ↓
                    合成：色散 / 扫描线 / 颗粒 / 反相 / 撕裂 / 暗角
                                     ↓
                    VideoEncoder (H.264 High, Annex-B) → fetch POST /chunk
                                     ↓
                    本地服务按序号落盘 → ffmpeg 与音轨封装
```

选择在**页面内**编码而不是逐帧截图，理由是它逐帧确定性、能跑到 ~152 fps（整支 MV 约
84 秒渲完），而且不会产生几十 GB 的中间 PNG。

### 零依赖工具链

不想为了一个 MV 装一整套 npm 生态，所以整条链路是零依赖的：

* **CDP 客户端**（`_dev/chrome.mjs`）—— 用 Node 自带的全局 `WebSocket` 直接讲
  DevTools Protocol。
* **静态服务 + H.264 分块汇聚**（`_dev/server.mjs`）—— 支持按字节精确回滚。
* **浏览器启动器**（`_dev/start-chrome.mjs`）—— 一个长期运行的无头 Chrome，
  所有后续脚本只通过 localhost 调试端口连它。
* **音乐特征烘焙**（`_dev/bake-audio.mjs`）—— 自己写的 radix-2 FFT，把 WAV 变成
  每帧一条的曲线 + 420 个瞬态点，存成 base64 uint16 的 `assets/analysis.json`。
* **分析图**（`_dev/plot.mjs`、`_dev/ssm.mjs`）—— 自己写的 PNG 编码器（zlib + CRC32），
  用来画曲线和自相似矩阵，把「歌长什么样」变成能看的图。
* **字体**（`_dev/get-font.mjs`）—— 直接从 npm registry 下 tarball 解出 woff2
  （JetBrains Mono，OFL），不装 npm 包。
* **音频**（`_dev/pyenv/` 里的 yt-dlp）—— 下载官方音轨；ffmpeg 只做解码 / 分析 / 封装。

### 关于「所有东西都在工作目录内」

本目录之外**没有安装、也没有写入任何东西**：

| 类别 | 位置 |
|---|---|
| 代码 | `index.html` `css/` `js/` `_dev/*.mjs` |
| 素材 | `assets/`（音轨、字体、烘焙好的音乐特征） |
| 工具 | `_dev/pyenv/`（yt-dlp，从 PyPI 下 wheel 解出来） |
| 依赖 | 无 —— 全链路零 npm / 零 pip 依赖 |
| 中间文件 | `_dev/tmp/`（H.264 码流、Chrome profile、下载缓存、分析图） |
| 最终产物 | `out/` |

只有两个**只读使用**的外部程序，它们本来就装在机器上，本作没有安装或改动它们：
`ffmpeg` / `ffprobe`（解码、分析、封装）和 DSH 自带的 Python（用来跑 yt-dlp）。
工作目录总共约 2.2 GB，其中 632 MB 是母版、143 MB 是分享版、624 MB 是中间码流
（保留下来是为了不改一帧就能重新封装）。

## 五、快速开始

### 当播放器用（浏览器里实时播放）

```bash
cd "World.Execute(me)/shot02"
node _dev/server.mjs --port=8802
# 浏览器打开 http://127.0.0.1:8802/index.html
```

空格播放 / 暂停，←/→ 逐帧步进，↑/↓ ±5 秒。
`?t=61.5&still=1` 定格某一帧。

### 重新渲染整支 MV

```bash
cd "World.Execute(me)/shot02/_dev"
node start-chrome.mjs --port=9333          # 一个长期运行的无头 Chrome
node capture.mjs --start=0 --end=12738 --chunk=1600 --bitrate=24000000
```

渲染进度写进 `_dev/tmp/capture-state.json`；**中断后直接重跑同一条命令即可续渲**
（H.264 码流按字节精确回滚到检查点，不会重复或丢帧）。
