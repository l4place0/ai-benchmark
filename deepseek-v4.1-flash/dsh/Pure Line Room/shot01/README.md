# 纯线房间 / Pure Line Room

一个纯浏览器、离线的互动矢量线稿房间。打开 `index.html` 即可运行：没有构建步骤、
没有网络请求、没有外部字体 / 图片 / 音频，所有几何、纹样与声音都是运行时生成的。

## 运行

```
双击 index.html          # 或拖进任意现代浏览器
```

首次点击画布后才解锁声音（浏览器的自动播放策略要求一次用户手势）。

## 操作

| 操作 | 效果 |
|---|---|
| 拖拽 | 环视房间（相机受过约束，不会穿进家具或墙体） |
| 滚轮 | 推拉镜头 |
| 点击物件 | 操作它；鼠标停住不动约 0.1 秒才会出现悬浮提示，方便环视时不误触 |
| 拖拽椅子 | 在房间里推着走，带轮子滚动、倾身、落定回摆 |
| `M` | 静音 |
| `L` | 开 / 关主灯 |
| `C` | 收起 / 合上近处那面墙（剖面视图） |
| `R` | 视角复位 |
| `T` | 锁定 / 解锁真实时间 |

## 技术

- **自写的软件 3D 渲染器**（`js/renderer.js`）：世界坐标 → 视图 → 透视投影 →
  裁剪 → 画家算法深度排序 → Canvas 2D 描边与填充。没有任何 3D 库。
- **线稿语言**（`js/scene.js`）：每个面 = 一次填充 + 若干显式描边，分四种线宽等级
  （轮廓 / 结构 / 构造 / 曲率提示），线宽随视距缩放，这就是平面图能读出空间感的原因。
- **材质键**：几何体里写 `@wall`、`@wood` 这样的键，绘制时才解析成当前昼夜状态的颜色，
  所以整间屋子会随环境重新"上墨"。
- **窗口**：东墙上真实开洞，窗外的世界作为独立图层在"外壳层"与"家具层"之间合成，
  并按投影后的洞口多边形 + 相机所在的墙体半空间做 3D 裁剪——没有挖洞、没有深度缓冲，
  墙、窗框、百叶、窗帘的遮挡关系全部正确。
- **拾取**：屏幕 → 世界射线（与投影共用同一套相机基向量，两者互为精确逆运算），
  再对注册物件做射线 / AABB 求交，`priority` 作为深度折扣，让小物件不会被大包围盒吞掉。
- **声音**（`js/audio.js`）：Web Audio 程序化合成，21 种一次性音效 + 5 条持续环境床
  （室内底噪、窗外昼夜环境与夜间虫鸣、唱片底噪与爆豆、吊扇电机、台灯电流声）。

## 自测

两套独立的验证设施，都会加载**真实的 `js/*.js`**：

**1. 真实浏览器（推荐）** —— `_dev/shot.mjs` 通过 Chrome DevTools Protocol 驱动
Chromium 打开 `index.html`，派发真实鼠标 / 键盘事件，截图并回读页面状态：

```
node _dev/shot.mjs --out=_dev/live.png --wait=8000          # 打开并截图
node _dev/shot.mjs --out=_dev/a.png \
     "--do=move@990,522;click@990,522;drag@830,616>700,700"  # 真实交互后再截图
node _dev/sweep.mjs                                          # 一次启动，多点机位对比
```

**2. 离线 Node 模拟器** —— `_dev/harness.mjs` 自带 DOM + Canvas2D 模型，无需浏览器即可
在 CI 里跑完整断言：

```
node _dev/verify.mjs        # 61 项断言：31 个可交互物件逐个定位→悬浮→点击→验证状态变化
node _dev/smoke_audio.mjs   # 音频引擎（模拟 Web Audio，373 项断言）
node _dev/room.mjs --out=_dev/shot.png --frames=340   # 用 Pillow 光栅化一帧
```

`_dev/verify.mjs` 覆盖：每个物件的可达性与点击效果、悬浮反馈、拖拽与点击的区分、
椅子拖拽的碰撞约束、连续动态（吊扇 / 唱片 / 摆锤 / 指针 / 风铃）、全局环境切换、
顶点有限性、材质键合法性、save/restore 平衡。

浏览器侧的验证还额外做了一次**真实射线遮挡测试**（`_dev/occlusion_probe.js`）：
对每个可交互物件从相机打一条射线并求交所有网格，确认"看得见"与"点得到"一致——
这正是发现并修掉"窗帘包围盒吞掉整个房间点击"这类问题的手段。
