# Mili《world.execute(me);》程序生成同人 MV — 过程与结果记录

记录日期：2026-10-07。工作目录：`World.Execute(me) MV/shot01`。

本项目完成了两版全长程序生成视频。两版均通过各自的媒体规格、完整解码和音轨核验；用户仍不满意作品质量。第一版明确获评 **C**；第二版交付后，用户表示“质量一言难尽，我还是不能给你更高的评分”，没有另给一个新的等级。

## 原始要求

制作 Mili《world.execute(me);》的完整程序生成同人 MV。制作前理解歌词、主题、情绪、叙事与音乐结构，再进行原创视觉诠释。画面使用浏览器 Canvas / WebGL 等程序生成，输出 1920×1080、60 FPS，长度至少覆盖原曲全长。

所有新增代码、素材、工具、依赖、中间文件与最终产物均要求保存在本工作目录及其子目录内。用户建议使用可用的媒体生成能力或公开素材，并在第一版后明确要求尽可能上网寻找参考。

## 制作过程

### 第一版：音乐资料、程序场景与全长导出

整理歌曲资料、歌词位置与音乐段落，取得《Miracle Milk》原版录音并测量长度。程序提取音频 RMS、低频能量和瞬态数据，结合人工段落定位，用于动画细节和节拍周期。该过程没有自动识别全部乐器声部。

第一版以程序花瓣曲面和轨道关系为主视觉，扩展为笼罩结构、空间柱廊、飞蛾、碎片及执行隧道。按全曲时间轴组织镜头、形态和声音能量，导出完整视频并检查代表静帧、相邻帧差异、完整解码与原曲音轨同步。设计与分镜见 [creative-treatment.md](research/creative-treatment.md)、[storyboard.json](research/storyboard.json)。

用户先要求继续，随后给出“评分：C”，并指出“对 MV 的理解不够，你可以尽可能的上网找参考”。

### 参考研究与第二版重新策划

检索歌曲官方资料、同曲同人作品、动画 MV、舞蹈 MV、概念 MV 与生成艺术作品。研究覆盖 14 组参考入口，阅读创作者及制作团队访谈，并实际查看《Growing Pains》公开文章的四张静帧。部分 YouTube / Vimeo 内容访问受限，没有据此声称完整观看全部参考视频。研究图像保存在 `research/references/`，用于分析。

复盘第一版时，认为居中雕塑与能量反应承担了过多内容，第二个主体缺少主动行为，文字解释多于画面建立，符号也缺少足够的动作因果。参考研究和具体诊断见 [mv-reference-study.md](research/mv-reference-study.md)。

第二版提出《爱的验收机》：两位没有固定性别的纸偶建立关系，蓝色纸偶不断改变自身以邀请对方；黄色纸偶主动选择离开后，蓝色纸偶重演曾经被回应的动作，重演逐轮消耗自身。纸带从连接与建家转为记忆、修补和限制。这属于原创解读，没有声称为歌曲官方剧情。方案见 [revised-treatment.md](research/revised-treatment.md)。用户随后要求“那就实现吧”。

### 第二版：纸偶、样片与全长渲染

实现 Canvas 2D 纸偶剧场：头部、眼睛、身体、四肢、手与衣服分别绘制，肘膝采用逆运动学；角色与纸带、房屋、门、植物、鸟、剪刀和机械均为程序图形。下载 Lennart Demes / ambientCG 的 CC0 纸张纹理，结合本地字体形成纸片材质。前半段安排双人舞、自身赠予、身份交换、共同的家和食物／猫形态；后半段安排离开、剪除记忆、机械重演、损失、配对空位、门内外对照与余留。

先输出两个带原曲的样片：

| 样片 | 原曲起点 | 时长 | 帧数 |
| --- | --- | --- | --- |
| [相遇样片](output/v2/qa/meeting_1080p60.mp4) | 14.6 秒 | 15 秒 | 900 |
| [重演样片](output/v2/qa/restoration_1080p60.mp4) | 147.66 秒 | 20 秒 | 1200 |

查看样片编码帧，并修正人物颈部连接、重复角色、遮挡顺序、表情和近景。保存 36 个全曲源动画检查时刻；对 12 个代表时刻进行随机跳转前后像素比对，检查画面求值是否受播放历史影响。这些检查没有包含外部观众评审。

连续全长绘制在约 54 秒的音乐位置触发 GTX 960 图形进程崩溃。导出方式改为 11 个独立浏览器会话：前十段各 1200 帧，最后一段 862 帧。逐段检查帧数和图形日志，再拼接完整视频。

首次拼接的时间戳检查发现视频起点推后约 23 毫秒，原因是片段 AAC 编码预滚使 concat 输入起点为负值。随后先无损提取片段纯视频，再拼接画面并统一编码完整原曲音轨。修正后的音视频均从零开始，视频没有进行第二次有损编码。

最终检查通过：12862 个呈现时间戳距理想 1/60 秒序列的最大误差约 0.000000333 秒；原曲与成片音频相关性为 0.999096600943704，测得偏移为 0 毫秒；18、62、150、200 秒附近各三张相邻帧均不同。全曲 16 帧索引从最终 MP4 提取，另查看了成片中的离开、重演、门内外对照与结尾代表画面。

实际时间轴见 [v2/storyboard.json](research/v2/storyboard.json)，实现与工程检查见 [v2/implementation-notes.md](research/v2/implementation-notes.md)，逐段日志在 `logs/v2/parts/`。第二版来源与纹理记录见 [README-v2.md](README-v2.md)、[source.json](assets/textures/v2/source.json)。

## 用户反馈与质量复盘

第一版用户明确评为 **C**，并要求加强对 MV 的理解和参考研究。第二版交付后的原话是：

> 质量一言难尽，我还是不能给你更高的评分

助手接受该评价。以下是助手对第二版的复盘判断，用户没有逐项确认这些诊断：

- 纸偶表演僵硬，意图、重量、停顿与情感变化的表现不足。
- 构图和动作反复使用，视觉事件的变化与摄影层次不足。
- 剪辑对音乐的回应单薄，高潮缺乏足够的冲击力。
- 叙事符号可以由说明解释，但实际观看中的情绪没有充分成立。
- 对成片质量的判断偏乐观，交付前的审片标准太低；曾将这些问题描述为已经解决，判断失准。

本项目的最终记录是：两版全长工程产物已完成，用户仍不满意作品质量。第二版没有获得更高评分，也没有获得艺术质量验收通过。技术验证和代表画面观察的范围应按上述实际记录理解。

## 第二版复现

在本目录的 PowerShell 中运行，所需工具已保存在 `tools/`：

```powershell
.\render-v2.ps1 --preview
.\render-v2.ps1 --qa
.\render-v2.ps1
.\verify-v2.ps1
```

源动画预览默认使用 `http://127.0.0.1:9461/`；两版预览使用相同端口，应分别运行。源 HTML 需要 HTTP 提供模块、音频与纹理。第二版分段导出会复用媒体与日志检查合格的已有片段。详细说明见 [README-v2.md](README-v2.md)。

### 观看与重现

直接播放成片，或打开 `output/watch.html` 使用章节跳转。交互预览和重渲染均使用项目内的工具，不需要全局安装 npm 包。

```powershell
# 在本目录执行；启动带音频播放和拖动进度的本地浏览器预览。
.\render.ps1 -Preview
# 打开 http://127.0.0.1:9461

# 生成分镜静帧。
.\render.ps1 -QA

# 重新导出完整 MV。
.\render.ps1

# 完整解码、音画同步、相邻帧与媒体规格核验。
.\verify.ps1
```

`src/mv.js` 是动画主体，包含 35 个镜头、程序花瓣曲面、轨道关系、笼罩结构、空间柱廊、飞蛾、碎片、红色执行隧道、声音能量映射和原创片中文字。`research/storyboard.json` 是分镜时间表。

渲染采用项目内 Chrome Headless Shell 的 WebGL 2.0 与 Canvas。每帧以 `frame / 60` 作为唯一时间输入，经原始 RGBA 管道交给 FFmpeg，避免实时录屏丢帧。动画在任意时间点直接求值，随机形态使用固定种子。视频没有通过重复低帧率画面凑出 60 FPS。

### 工作目录约束

所有新增代码、下载素材、项目工具、依赖、浏览器配置、缓存、中间音频、日志、静帧和视频都保存在本目录或其子目录。Node、FFmpeg、FFprobe 已复制到 `tools`；Chrome 和 Three.js 下载到 `tools`。`TEMP`、`TMP`、浏览器 profile、磁盘缓存和崩溃目录显式指向本目录。没有执行全局包安装。

内置图像生成工具的默认输出目录位于项目之外，因此本项目使用下载的 NASA 图像和开放字体作为外部素材。
