# world.execute(me); — A Botanical Machine

Mili《world.execute(me);》完整程序生成同人 MV。

**用户最终评分：C。** 本记录包含制作过程、用户反馈、修订和交付结果。技术检查通过不等同于创作质量获得认可；本项目的最终评价以用户评分为准。

## 任务与约束

- 理解歌曲的歌词、主题、情绪、叙事和音乐结构，再进行原创视觉诠释。
- 使用浏览器 Canvas / WebGL 程序生成画面，交付 1920×1080、60 FPS、长度覆盖歌曲全长的视频。
- 所有任务代码、素材、工具副本、依赖、缓存、中间文件及最终产物保存在本工作目录及子目录内，不进行全局安装。

## 制作过程

### 第一版

研究歌曲及歌词，将故事诠释为依恋、控制、失联与反复执行的循环。以朱红金属花作为主体，白花代表另一主体，圆环、复制花园、几何牢笼及碎片承担关系变化的视觉叙事。详细创作说明与当时参考来源保存在 [导演笔记](docs/DIRECTORS-NOTE.md)。

使用 Three.js / WebGL 构建三维场景，Canvas 绘制文字与叠加效果；采用 Poly Haven 的 CC0 HDR 环境光素材。Node.js、浏览器、Playwright、FFmpeg 等使用目录内的本地副本。图像生成器的默认写入位置与目录限制冲突，因此未调用；使用公开 HDR 素材及程序化几何完成画面。素材与依赖来源见 [素材记录](docs/ASSETS.md)。

第一版用社区歌词时间戳组织 34 个镜头，并读取真实音轨的响度和频段包络；按每 18 秒分段渲染后拼接，输出 216 秒完整视频。其问题是过度依赖粗略歌词时间及匀速运动，未有效验证音乐重拍与转场的对应关系。

用户反馈原文：

> 这做的太烂了吧？作为MV至少节奏转场要和原曲对齐吧？

### 第二版：重做音乐剪辑

1. 音源改为 [Mili 官方账号 ProjectMili 发布的视频](https://www.bilibili.com/video/BV1ds411e7df/)音轨，保存为 `assets/song-official.m4a`，时长 212.3305 秒。
2. 使用目录内 Essentia.js 多特征节拍检测和音轨频谱通量分析，拟合约 130.002 BPM、0.244 秒节拍相位，再对局部瞬态峰值进行细化。
3. 建立 446 个拍点和 114 个镜头节点。结构切镜与人声弱起分别处理；主歌保留较长乐句，副歌按小节换镜，连续执行段按两拍推进，六次计数及其后的执行动作单独设置落点。
4. 让花瓣、圆环、镜头冲击和碎片响应拍点；失联段暂停主要运动。移除固定暗场转场及大部分常驻小字，调整机位和画面节奏。
5. 浏览器按音轨时间逐帧求值，WebCodecs 编码，FFmpeg 拼接并混入完整官方音轨；末尾补足至 216 秒。补修计数后的动作衔接，并重新输出受影响片段及完整视频。
6. 导出副歌、执行／计数段的带声音校准样片；样片底部显示拍点与切镜标记，正式成片没有校准条。抽帧检查关键场景及计数后的动作，完成全片解码和文件校验。

自动检测的拍点不代表已经逐字人工听审。检查中不超过 8.334ms 的数值仅表示选定落点量化到 60 FPS 帧网格的误差，不代表音乐理解或听感对齐的误差。

## 预览与复现

双击 `preview-v2.cmd` 打开第二版浏览器预览，点击 PLAY FILM 开始带声音播放；支持拖动时间与全屏。双击 `render-v2.cmd` 导出并验证第二版。

渲染按 18 秒分段进行，自动跳过带 `.done` 标记的已完成片段。如改动画面或时间轴，应先移走受影响的 `revision02/renders/segment_*.mp4` 及对应 `.done` 文件，再重新导出，避免复用旧片段。

第一版的入口为 `preview.cmd` 与 `render.cmd`。导演笔记及原始素材记录中的旧时间轴、镜头数量和旧音源描述属于第一版；第二版数据以上述修订记录及 `revision02` 内文件为准。

## 主要工程文件

- `revision02/src/film-v2.js`：第二版场景、镜头、动画与 Canvas 叠加。
- `tools/rhythm-v2.cjs`：实际音轨节拍与频谱分析。
- `tools/timeline-v2.cjs`：拍点、镜头及人声事件时间轴。
- `tools/render-v2.cjs`：浏览器逐帧渲染、分段编码、合成及样片输出。
- `tools/verify-v2.cjs`：章节、媒体验证、抽帧、总览和校验值输出。
- `src/film.js`、`tools/render.cjs`、`tools/analyze.cjs`：第一版实现。

所有上述任务文件保存在 `shot01` 内；`tools` 为本地工具与依赖，`cache` 为浏览器用户数据，`temp` 为临时文件。
