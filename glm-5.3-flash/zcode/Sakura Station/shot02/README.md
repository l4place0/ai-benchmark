# 桜ヶ丘駅 · Sakura Station — shot02

三渲二（日式卡通渲染）樱花车站 Three.js 场景。春日午后四点的日本近郊小镇：小型地面车站、双轨铁路、进站停靠（车门敞开）的两节编组电车、放下降杆的铁路道口，以及被盛开的樱花与飘落花瓣覆盖的商店街与住宅区。

- **当前状态**：可运行、可漫游；针对首版评审（评级 C，指出"车窗垂直于车身"等建模错误）已完成同类错误的全面排查与修复，见下文[工作过程记录](#工作过程记录)与[已知问题](#已知问题与限制)。
- **运行**：双击 `index.html` 即可（Three.js 已内置 `vendor/`，离线可用）；或在该目录起静态服务器后访问。固定随机种子，每次打开布局一致。
- **操作**：左键拖动环绕 / 滚轮缩放 / 右键平移；`1 / 2 / 3` 切换「站前定场 · 站台 · 道口」机位；`C` 进入漫游模式（Pointer Lock + WASD，Shift 加速），再按 `C` 返回。

## 工作过程记录

### 阶段 0：搭建（初版）

按提示词 20 个章节搭建 7 个模块（`core / environment / buildings / street / nature / actors / main`，经典 script 全局命名空间，兼容 file://）。本地起 Node 静态服务，用内置浏览器逐机位截图自测。

### 阶段 1：相机与遮挡（自测发现 6 类问题）

| 问题 | 根因 | 修复 |
| --- | --- | --- |
| 画面全空，相机落在原点附近地底 | `flyTo()` 传入数组却按 `.x/.y/.z` 取值，全为 `undefined` | `flyTo` 兼容数组并对俯仰角/距离做限幅 |
| 预设机位收敛极慢 | 相机阻尼 `dt` 被钳制在 50ms，低帧率环境（软件渲染 ~1fps）下收敛比真实时间慢 20 倍 | 阻尼改用未钳制的 `dtr`（≤0.5s），低帧率下仍按真实时间收敛 |
| 画面中部大面积"绿色空白" | **地面平面漏写 `rx:-π/2`，实际是一堵竖立在 z=0 的 460×460 巨墙**，挡住全部北侧内容 | 补上旋转；射线检测验证站牌方向已通 |
| 车站被西侧建筑完全遮挡 | 站房横跨 x=-34..2 且主立面朝南，视线被咖啡店+行道树堵死 | 站房缩至 x=-26..-6、主立面改朝东（面向马路），站牌升至 y=4.3 高于西侧店房屋顶线；咖啡店与花店位置互换（矮花店靠近车站侧），原址改停车场，视线走廊打通 |
| 街道电杆之间没有电线 | `WireBank.build()` 在街道模块收集线段**之前**执行 | 移到全部模块构建完成之后统一构建 |
| 站台长椅、站牌"消失" | 长椅忘记加 1.02m 站台面高度（埋进台体）；吊挂站牌 x 位置在站房范围外 | 长椅增加 y 参数；站牌移至站房开口对应位置 |

### 阶段 2：造型与色彩（自测发现 8 类问题）

樱花树冠由"离散气球"改为高密度小花簇（数量 ≈ 40+5R，受光面亮粉 / 背光面紫灰 / 2% 新叶）；树干折痕、干粗比例修正；树冠整体抬高（冠底 ≥ 冠心-0.55R），车站与店铺从冠下露出形成"樱花拱廊"；天空地平线色与地面基色去黄绿；道床碎石提暖；站台阴影提亮（toon 最低档 0.42→0.52）；站房屋面板缝坐标、售票机朝向、便利店侧墙窗、和菓子店/花店缺失的屋顶等补齐。

### 阶段 3：评审反馈修复（评级 C → 针对性返工）

评审意见："细看模型充满大量错误，如车辆的窗户全是打开的（也许是错位？表现形式为窗户垂直于车身），还有其他错误不再赘述。"

**根因定位**：`box(宽, 高, 深)` 的薄片方向写反。侧窗写成 `box(0.06, 高, 宽)`——薄片沿 X（车长方向）、宽边沿 Z（车宽方向），整排窗玻璃像鳍片一样**垂直插在车体侧面**，视觉上就是"窗户全开着/错位"。评审所见即此 bug。

**同类错误全面排查**（凡"薄片应贴着的面"与"薄片方向"不符即改）：

| 位置 | 错误表现 | 修复 |
| --- | --- | --- |
| 电车侧窗 ×16 | 玻璃垂直车身伸出 | 改为 `box(1.55, 0.85, 0.06)`，薄片贴侧面 |
| 电车窗框 ×16 | 同上 | 同步修正 |
| 车内乘客剪影 ×若干 | 垂直车身 | 同步修正 |
| 车门门洞 ×8 / 收进式门叶 ×8 / 门口黄线 ×8 | 垂直车身伸出 | 门洞 `box(1.32, 1.8, 0.06)`、门叶 `box(0.62, 1.8, 0.04)`、黄线 `box(1.36, 0.09, 0.07)` |
| 车辆编号牌 / 公司标志 | 贴在侧面却旋转 90° 侧立 | 取消旋转，平贴侧面 |
| 车站东门双开门 | `ry = π/2-s*0.42` 把门叶转到与墙面垂直 | 改为 `ry = s*0.42`（门叶与墙平行、微张开） |
| 咖啡店大门 / 花店大门 | 门板垂直于迎街面伸出 | 薄片方向改为贴墙 |
| 便利店玻璃幕墙 | 平面法线朝店内，从街上看不见 | 转为朝外（DoubleSide） |
| 便利店招牌带 | 盒体 UV 导致文字镜像风险 | 改为独立朝外贴图平面 + 中性底盒 |

修复后经三机位截图复核：站台视角下侧窗、色带、门洞、门叶均与车身平行贴合（见下方"结果"）。

### 验证方式

本地 Node 静态服务 + 内置浏览器（1280×720 / 1600×900）逐机位截图；投影关键点到屏幕坐标核对构图；Raycaster 射线检测确认站牌通视；逐物体射线检测定位遮挡物（借此发现地面墙 bug）；每轮修改后 `node --check` 全量语法校验。

## 已知问题与限制

1. **电车内饰极简**：车窗为不透明色块，"乘客剪影"位于玻璃之后实际不可见；车内没有座椅/扶手建模。
2. **人物无面部细节**：人物为 0.6~0.7m 简化比例（头/发/上下装/书包），近看无五官与手部。
3. **列车静止**：电车为停站状态（车灯常亮、门开、指示灯绿），没有行驶动画；道口杆保持放下属于场景摆拍设定。
4. **雨棚结构简化**：站台雨棚为单排柱+悬挑板，无斜撑与檩条细节；站台西侧无楼梯/坡道与地面连通（漫游模式靠高度补丁直接上台）。
5. **远景层次有限**：远山在雾中较淡，北侧住宅群之外只有剪影级实例化房屋；场外东侧无河堤。
6. **招牌文字依赖系统字体**：Canvas 贴图使用 Yu Gothic / Meiryo 等系统字体，在无日文字体的系统上会回退为默认字形。
7. **性能**：~800 次绘制调用、17 万三角形、2048 阴影贴图；独立显卡 60fps 无压力，核显或软件渲染帧率会明显下降（相机阻尼已按真实时间收敛，不受影响）。
8. **物理与碰撞**：漫游模式无碰撞，可穿入建筑内部；地面高度仅对站台/广场做了补丁。
9. **部分盒体贴图 UV**：箱体六面共享贴图，个别角度（如自动贩卖机背面）文字方向不严谨，正面均使用独立平面规避。

## 三渲二渲染

- `MeshToonMaterial` + 4 级 gradientMap（0.52/0.72/0.90/1.00），阴影不死黑；
- 反向外壳描边（顶点着色器沿法线恒定世界厚度偏移）：站房/电车/树干/电杆/贩卖机深棕描边，树冠梅紫描边；
- 暖阳平行光（1.28，侧后方）+ 半球天光 + 相机侧冷补光，PCFSoftShadowMap 2048；
- 天空自定义渐变穹顶着色器 + 太阳方向暖色增益，太阳光晕 sprite，薄云漂移；
- 雾 `#d5e9f2`（90→300m）衔接天际，远山与远景房屋剪影分层退晕；
- 全部日文标牌/海报/黑板/面板为 Canvas 程序化贴图，无外部资源。
